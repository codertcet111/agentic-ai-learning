Freshness and re-indexing

Keep a RAG index fresh: detect document changes with content hashes, re-embed only changed chunks, version documents atomically and handle deletions and model upgrades.

Shubham Mishra2 min read

A retrieval system that answers from last quarter's policy is worse than one that says "I don't know". Users trust the citation and act on it. Freshness is about making sure the index follows the source documents closely and visibly.

Know your sources

For each collection, record where documents come from and how you learn about changes:

SourceChange signalSync strategy
CMS or intranetWebhook on publishRe-index the single document on event
SharePoint / Google DriveChange feed or modified timePoll every few minutes for changes
Git-hosted docsCommitsCI job on merge to main
Files with no APINoneNightly full scan with hashes

Hash to skip unchanged work

Embedding costs money and time. Compute a hash of each document's normalized text. If it matches the stored hash, skip it. When it differs, chunk the new version and hash each chunk. Chunks whose hash already exists can reuse their stored embedding, and only new or changed chunks get embedded. For a policy where one paragraph changed, that means re-embedding one or two chunks, not forty.

Swap versions atomically

  1. Write the new version's chunks with document_version = n + 1 and active: false.
  2. When all are written and embedded, set active: true on version n + 1 and active: false on version n.
  3. Delete inactive versions after a grace period.

Queries always filter on active: true, so users never see a mix of old and new chunks from the same document.

Deletions

Deleted source documents are the most commonly missed case. A withdrawn policy that is still in the index will keep being cited. Full scans should compare the set of document ids in the source with the set in the index and deactivate anything missing. Event-based syncs need to handle delete events explicitly.

Show freshness to users

Include the document's last-modified date in citations: "Annual Leave Policy (updated 3 Sep 2026)". Users can judge for themselves, and it encourages document owners to keep sources current.

Monitor lag

Track, per collection, the time between a source change and the index reflecting it, and the age of the most recent sync. Alert if a sync has not succeeded within twice its expected interval. A silently broken sync job is the usual way an index goes stale.

Embedding model upgrades

A new embedding model means re-embedding everything, because vectors from different models are not comparable. Build the new index alongside the old one, run your retrieval evaluation against both, switch query traffic when the new one is at least as good, then remove the old one.
