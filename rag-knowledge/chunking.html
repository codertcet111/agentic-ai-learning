Chunking strategies

Practical chunking strategies for RAG: structure-aware splitting on headings and paragraphs, chunk sizes, overlap, metadata for citations and how to test your choices.

Shubham Mishra2 min read

Chunking decides what the retriever can find. If a policy's key sentence is split across two chunks, or buried in a chunk dominated by an unrelated table, no embedding model and no prompt will recover it. Chunking is the least glamorous part of RAG and one of the most important.

Split on structure first

Documents already have structure: headings, sections, paragraphs, list items, table rows. Use it.

  1. Parse the document into a tree of headings and blocks (Markdown and HTML are easy; for PDFs and Word files use a layout-aware parser).
  2. Walk the tree and emit one chunk per section, or per paragraph group within a section.
  3. Only when a single section is too long, split it further on paragraph boundaries, then on sentence boundaries. Never cut mid-sentence.

Fixed-size character splitting is fine for a prototype. It is rarely the best choice for policies, handbooks and documentation.

Size

There is no universal right size, but there are useful starting points:

ContentStarting sizeReason
Policies, handbooks200–400 tokensOne rule or clause per chunk keeps answers precise
How-to guides300–600 tokensSteps need their surrounding context
FAQsOne Q&A pairThe natural unit already exists
TablesRow groups with header repeatedA row without its header is meaningless

Smaller chunks retrieve more precisely but lose context. Larger chunks keep context but dilute the embedding. Measure, do not guess (see evaluating retrieval).

Overlap

When you must split inside a section, overlap neighbouring chunks by about 10–15% so a sentence that depends on the previous one is not orphaned. With structure-aware splitting, overlap matters less: a heading boundary is a natural break and needs no overlap.

Add context to each chunk

A chunk that says "This limit does not apply to part-time staff" is useless on its own. Prepend its heading path before embedding:

Annual Leave Policy > 4. Carry-over > 4.2 Limits
Employees may carry over up to five days into the next leave year.
This limit does not apply to part-time staff, whose carry-over is pro-rated.

This one change often improves retrieval more than switching embedding models. Some teams go further and generate a one-sentence summary of the whole document to prepend to each chunk. That costs one LLM call per document at indexing time, which is usually affordable.

Metadata for citations

Every chunk stores its source URI, title, heading path, page number or anchor, and document version. Compose uses these to cite, and the UI uses them to link to the exact section. See vector metadata for the full schema.

Things to strip

  • Repeated headers and footers from PDFs ("Company Confidential – Page 3 of 18").
  • Tables of contents. They match every query and answer none.
  • Navigation text from scraped web pages.
