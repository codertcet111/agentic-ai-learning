Agentic Development

A twenty-step path to designing and shipping an agentic backend that holds up in production.

Your progress0 of 20 complete

Read these in order. Each step builds on the one before, from drawing the boundary between your agent and your business APIs to freezing behaviour with golden tests. Examples use a fictional HR assistant so you can map the ideas onto your own domain.

  1. 01Draw the orchestration boundary3 minSeparate the LLM orchestration layer from your domain APIs before writing a line of agent code, and decide which layer owns rules, data, and permissions.
  2. 02Layer API, services, agents, providers2 minStack an agentic backend as API routes, application services, graph agents and outbound providers, with imports that only point downward so each layer stays testable.
  3. 03Keep auth in request context, not graph state2 minKeep auth tokens, cookies and forwarding identifiers in per-request context instead of graph state, so they never reach checkpoints, logs, traces or the model.
  4. 04Model sessions and conversations2 minModel sessions (who is chatting and under what scope) separately from conversations (individual chat threads with revisions, limits and lifecycle).
  5. 05Admit turns with leases and fences2 minAdmit each chat turn with a compare-and-set fence on the conversation revision and a turn ledger in MongoDB, using Redis only as an advisory shortcut.
  6. 06Map Mongo collections to roles2 minA map of the MongoDB collections an orchestration service needs, what each one owns, and how to declare indexes once and create them at startup.
  7. 07Append messages, don't mutate arrays2 minStore chat transcripts as append-only message documents with a per-conversation sequence and idempotency keys instead of growing arrays inside one document.
  8. 08Pending forms and exact resume2 minPause agent workflows with durable pending interactions (forms and confirmations) and resume them only through a typed form submission matching id and revision.
  9. 09Merge and pin the capability catalog2 minMerge capability catalogs from upstream services, normalize their schemas, hash the result and pin that version per session so tools never change shape mid-conversation.
  10. 10Provider adapters and invoke2 minBuild provider adapters that invoke domain capabilities with shared HTTP pools, explicit timeouts, bounded retries, circuit breakers and typed error envelopes.
  11. 11Wire LangGraph with a checkpointer2 minWire a LangGraph StateGraph with typed state, async nodes, pure routing functions and a MongoDB checkpointer, compiled once at application startup.
  12. 12Walk the node pipeline2 minA walk through a production agent graph pipeline: load session, route, plan, resolve arguments, invoke, evaluate conditions, request input and compose the reply.
  13. 13Typed Pydantic outputs for every LLM call2 minBind every LLM call to a Pydantic output schema, validate strictly, repair once on failure and keep policy text in one place instead of scattered prompts.
  14. 14Resolve arguments without smuggling ids2 minResolve tool arguments by enriching context with lookups and replanning, rather than letting resolver code quietly choose entity ids on the model's behalf.
  15. 15Known commands before the model2 minHandle known commands such as reset, help or show usage with exact-match recipes before the LLM runs, for predictable, cheap and auditable behaviour.
  16. 16Presentation modes and bilingual compose2 minLet structured results render as tables, cards or forms through presentation modes, while compose still produces bilingual fallback text for every reply.
  17. 17Redis for catalog, caps, and locks2 minUse Redis for catalog caches, capability snapshots, rate limits and advisory locks with versioned, namespaced keys, explicit TTLs and graceful fallback when Redis is down.
  18. 18Trace requests, nodes, and LLM calls2 minTrace every agent turn from request id to conversation, graph run, nodes, LLM calls and tool invokes, with pseudonymized identifiers and no secrets in span attributes.
  19. 19Add RAG without breaking the graph2 minAdd retrieval-augmented generation to an agent graph as a capability or a dedicated sub-agent, with citations, permission filtering and evaluation before launch.
  20. 20Golden evals and regression gates2 minFreeze agent behaviour with golden JSON cases covering routing, tool choice, multi-turn flows and safety, run in CI with stubbed models and nightly against real ones.
