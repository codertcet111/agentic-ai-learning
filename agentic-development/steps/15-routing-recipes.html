Known commands before the model

Handle known commands such as reset, help or show usage with exact-match recipes before the LLM runs, for predictable, cheap and auditable behaviour.

Shubham Mishra2 min read

Not every message needs a model. "Reset conversation", "show my usage", "help", "talk to a human": these have one correct answer, and sending them through a planner adds cost, latency and a small chance of getting them wrong. Routing recipes handle them before the LLM runs.

What a recipe is

RECIPES = [
  Recipe(
    id="reset_conversation",
    aliases={"en": ["reset", "reset conversation", "start over", "clear chat"],
             "ar": ["إعادة تعيين", "ابدأ من جديد", "مسح المحادثة"]},
    handler=reset_conversation,
  ),
  Recipe(
    id="show_usage",
    aliases={"en": ["usage", "show usage", "my usage"],
             "ar": ["الاستخدام", "عرض الاستخدام"]},
    handler=show_usage,
  ),
]

A recipe has an id, a list of aliases per language, and a handler that returns a fixed or data-driven response. The handler is ordinary code and may call a capability, but it never calls the LLM.

Matching rules

  • Normalize first: trim, lowercase, collapse whitespace, strip trailing punctuation, and normalize Arabic letter variants (alef forms, taa marbuta) and diacritics.
  • Match the whole message exactly against aliases. "Reset" matches; "how do I reset my password" does not.
  • No fuzzy matching. Near-misses go to the planner, which can handle them, and an exact list stays easy to audit.

Why bother

  • Reliability. Support scripts and onboarding demos say exact phrases. They should work identically every time.
  • Cost. A meaningful share of messages in internal assistants are short commands. Serving them without a model call adds up.
  • Security. Sensitive operations such as "delete my data" or "export my conversation" get one deterministic, reviewed path.
  • Latency. Recipes reply in milliseconds.

Recipes in the graph

route_request checks recipes first. On a match it sets recipe_id in state and routes to a recipe node that runs the handler and writes the response directly, with response_finalized set. Recipes still go through turn admission, still persist messages, and still emit traces, tagged route=recipe so you can count them.

UI shortcuts

Recipes pair well with quick-reply chips. A "Show usage" chip sends the canonical alias, so the click is guaranteed to hit the recipe. It is the same path as typing, which keeps behaviour consistent and testable.

Keep the list short

Recipes are for commands, not for questions. If you find yourself adding "what is the leave policy" as a recipe, that is a sign you want retrieval (step 19) or a better capability card. A good recipe list fits on one screen and changes rarely.
