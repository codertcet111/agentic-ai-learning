Step 17 — Redis for catalog, caps, and locks

Use Redis for catalog caches, capability snapshots, rate limits and advisory locks with versioned, namespaced keys, explicit TTLs and graceful fallback when Redis is down.

2 min read

Redis makes an orchestrator fast. It should never make it correct. Every pattern in this step follows one rule: if Redis disappears, the system gets slower, not wrong.

Key naming

Keys carry a version prefix, a purpose, a tenant and an entity id:

v3:catalog:merged:{hash}                 → merged catalog JSON
v3:caps:{tenant}:{principal_id}           → allowed capability ids
v3:lease:turn:{conversation_id}           → advisory turn lease
v3:rl:{tenant}:{principal_id}:{minute}    → rate limit counter
v3:lookup:{tenant}:{capability}:{qhash}   → short-lived lookup cache

The version prefix lets you change value formats by bumping v3 to v4 on deploy, with no flush and no mixed-format reads. Including the tenant in keys prevents a whole class of cross-tenant leaks caused by a missing argument.

TTL on everything

Every SET has an expiry, and the TTL is documented next to the key definition:

KeyTTLWhy
catalog:merged24 hImmutable by hash; TTL only reclaims memory
caps5 minPermission changes should take effect quickly
lease:turnMax turn duration + marginMust expire if a worker dies
rl2 minFixed-window counter
lookup30–120 sSmooths repeated searches within a turn

A key without a TTL is a memory leak waiting for a busy week.

Read-through with fallback

async def get_catalog(hash_: str) -> Catalog:
    try:
        raw = await redis.get(f"v3:catalog:merged:{hash_}")
        if raw:
            return Catalog.model_validate_json(raw)
    except RedisError:
        log.warning("redis_unavailable", op="catalog_get")
    cat = await catalog_repo.get(hash_)                 # Mongo is the source
    with suppress(RedisError):
        await redis.set(f"v3:catalog:merged:{hash_}", cat.model_dump_json(), ex=86400)
    return cat

Errors from Redis are logged and swallowed on reads. The fallback path is the real path.

Leases are advisory

The turn lease (SET … NX PX) bounces duplicate submissions early. MongoDB's compare-and-set on the conversation revision (step 5) is the real gate. If the lease is lost, two requests reach Mongo and one still loses. Never skip the Mongo check because the lease succeeded.

Rate limits

A simple fixed-window counter (INCR plus EXPIRE on first increment) per principal per minute is enough for most internal assistants. If Redis is down, choose deliberately: fail open (allow the request) for low-risk reads, or fall back to a coarse in-process limiter. Write that decision down.

Chaos test

Run your integration suite once with Redis stopped. Turns should still be admitted, catalogs loaded, and messages persisted, only slower. If anything fails, you have found a place where Redis became the source of truth by accident.
