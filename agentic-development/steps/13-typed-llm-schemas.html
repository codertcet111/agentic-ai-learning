Step 13 — Typed Pydantic outputs for every LLM call

Bind every LLM call to a Pydantic output schema, validate strictly, repair once on failure and keep policy text in one place instead of scattered prompts.

2 min read

An agent graph is only as reliable as the weakest LLM output it accepts. If any node parses free text with regular expressions or trusts a JSON blob without validating it, that node is where the 3 a.m. bug lives. The rule for this step is simple: every LLM call returns a Pydantic model.

One schema per purpose

from pydantic import BaseModel, Field
from typing import Literal

class PlanDecision(BaseModel):
    kind: Literal["call_tool", "need_input", "answer"]
    capability_id: str | None = None
    intent: str = Field(max_length=300)
    missing: list[str] = []

class ArgumentFill(BaseModel):
    arguments: dict
    unresolved: list[str] = []
    needs_lookup: str | None = None

class ConditionResult(BaseModel):
    result: bool
    reason: str = Field(max_length=200)

class ComposePayload(BaseModel):
    text_en: str
    text_ar: str
    follow_up_suggestions: list[str] = Field(default_factory=list, max_length=3)

Keep these in one schemas module. Prompts, stubs and tests all import from there, so there is one source of truth for what each step produces.

Use the provider's structured output support

Most model APIs now support constraining output to a JSON Schema, either through tool or function calling or through a dedicated response format option. Pass PlanDecision.model_json_schema() through your gateway and you will get syntactically valid JSON nearly every time. You still validate with Pydantic, because a valid shape can still carry invalid values, such as a capability_id that is not in the catalog.

Validate, repair once, then fail safe

async def call_typed(llm, prompt, schema: type[T]) -> T:
    raw = await llm.complete(prompt, response_schema=schema)
    try:
        return schema.model_validate_json(raw)
    except ValidationError as e:
        repaired = await llm.complete(repair_prompt(raw, e, schema),
                                      response_schema=schema)
        return schema.model_validate_json(repaired)   # raises if still bad

One repair attempt is enough. If the second call also fails, raise a typed error that the graph turns into a polite apology and a failure record. Unbounded repair loops are how a single bad turn becomes a large bill.

Semantic validation

Add validators that check values against the turn's context:

  • capability_id must be in the filtered catalog for this session.
  • arguments must validate against that capability's parameter schema.
  • Dates must be real dates and, where relevant, not in the past.

Pass the context in with Pydantic's validation context rather than global state.

Keep policy in one home

The prompt for each call has two parts: the schema (what shape to return) and the policy (how to decide). Put node-level policy in the graph definition module and persona and voice in the agent definition. Do not repeat "never invent an employee id" in five prompts. When rules are duplicated, they drift, and the model receives conflicting instructions.

Schema changes are contract changes

When a schema changes, update in the same pull request: the prompt examples, the stub LLM fixtures (LLM_STUB) and the golden cases that assert on it. CI that runs against stale stubs reports green while production breaks.

Developer POV: When schema changes, update stub LLM fixtures in the same PR or CI will lie.
