Step 3 — Keep auth in request context, not graph state

Keep auth tokens, cookies and forwarding identifiers in per-request context instead of graph state, so they never reach checkpoints, logs, traces or the model.

2 min read

LangGraph and similar frameworks persist graph state between nodes and across pauses. That is what makes resumable workflows possible. It also means that anything you put in state can end up in a database document, a trace export or a debug log. Credentials must never be there.

Two kinds of data in a run

  • Graph state: what the workflow is doing. The current plan, resolved arguments, tool results by reference, the pending form id. Safe to checkpoint and inspect.
  • Request context: who is asking and how to call upstream on their behalf. Access token, tenant id, locale, correlation id. Rebuilt on every request, never persisted.

In LangGraph the natural home for the second kind is the run configuration, for example config["configurable"]["request_context"]. Nodes and providers read it; the checkpointer does not save it.

A minimal request context

from dataclasses import dataclass, field

@dataclass(frozen=True)
class RequestContext:
    request_id: str
    tenant_id: str
    locale: str
    forwarded_headers: dict[str, str] = field(repr=False)

    def redacted(self) -> dict:
        return {"request_id": self.request_id,
                "tenant_id": self.tenant_id,
                "locale": self.locale}

Note repr=False on the headers. A stray print(ctx) or a logged exception will not leak the token. The redacted() helper is what goes into logs and trace metadata.

Building it in middleware

@app.middleware("http")
async def attach_context(request, call_next):
    ctx = RequestContext(
        request_id=request.headers.get("x-request-id") or new_id(),
        tenant_id=resolve_tenant(request),
        locale=request.headers.get("accept-language", "en")[:2],
        forwarded_headers={"Authorization": request.headers["authorization"]},
    )
    request.state.ctx = ctx
    return await call_next(request)

The service layer passes ctx into the graph config when it starts a run. Providers read forwarded_headers when they build each outbound request.

Shared HTTP clients and cookies

For performance you will share one HTTP client across requests. That client must not keep a cookie jar. If an upstream sets a session cookie for user A and the pooled client stores it, user B's next request may carry it. Disable cookie persistence on the shared client and attach auth explicitly on each call.

Redaction at every exit

There are four common exits where secrets leak: application logs, error trackers such as Sentry or Rollbar, LLM observability tools, and database documents. Put one redaction helper in front of each:

  • Log formatters drop known header names and anything matching token patterns.
  • Error tracker hooks scrub request headers and local variables.
  • Trace exporters run a masking pass before upload (see the Langfuse Lab section).
  • Repositories accept typed models that simply have no field for credentials.
Being able to see a tool is not the same as being allowed to call it. Check permissions when the tool is called, and let the upstream API check again.

A test that should always pass

Write one test that runs a full graph turn with a fake token such as Bearer test-secret-123, then serialises every checkpoint, every persisted message and every captured span and asserts the string test-secret-123 appears in none of them. It is cheap to write, and it catches the day someone adds headers to graph state "just for debugging".

Developer POV: Grep your codebase for token strings in GraphState or checkpoint tests—should return zero hits.
