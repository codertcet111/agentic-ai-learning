Inference: latency, throughput and cost

What AI engineers need to know about LLM inference: time to first token, throughput, batching, KV cache, quantization, streaming, caching and the trade-offs between hosted APIs and self-hosting.

Shubham Mishra2 min read

Users judge an assistant by how fast it feels, and finance judges it by what it costs. Both come down to inference: the work of running the model for each request. You do not need to write GPU kernels, but you should know the vocabulary and the levers.

Two latencies, not one

  • Time to first token (TTFT): how long before anything appears. Driven by queueing, network and processing the input prompt. Long prompts raise it.
  • Output speed: tokens per second once generation starts. Driven by model size and server load. Long replies take proportionally longer.

Total time is roughly TTFT plus output tokens divided by speed. An agent turn often makes several calls in sequence, so these add up quickly.

What happens on the server

TechniqueWhat it doesWhy you care
BatchingProcesses many requests together on the same hardwareHigher throughput and lower cost per token; can add a little queueing delay
KV cacheKeeps attention state for tokens already processedMakes generating each new token cheap; also enables prompt caching
Prompt cachingReuses work for a repeated prompt prefix across requestsCheaper, faster input when system prompt and tools stay identical
QuantizationStores weights in fewer bits (for example 8 or 4)Fits larger models on less hardware, faster, with some quality risk
Speculative decodingA small model drafts tokens that the large model verifiesFaster output with the large model's quality

Levers you control

  1. Fewer calls per turn. Recipes, better tool descriptions and summarised tool results cut replanning (see cost controls).
  2. Smaller prompts. Filter tools, trim history, summarise retrieved text.
  3. Stable prefixes. Put unchanging content first so prompt caching applies.
  4. Right-sized models. Small models for routing and extraction, large ones for hard planning (see model routing).
  5. Streaming. Users perceive speed from the first words (see streaming).
  6. Parallel calls. Run independent tool calls and reads concurrently.
  7. Cap output. Set max tokens per purpose.

Hosted API or self-hosted?

Hosted APISelf-hosted open model
Start-up effortMinutesDays to weeks
Cost at low volumeLow, pay per tokenHigh, you pay for idle GPUs
Cost at steady high volumeCan become significantCan be lower if utilisation is high
Data controlDepends on provider terms and regionFull
Model quality ceilingUsually highestDepends on available open models
OperationsProvider's problemYours: scaling, upgrades, monitoring

Many teams start hosted, measure real usage for a few months, and only then consider self-hosting specific high-volume, narrow tasks.

Measure it

Record TTFT, total duration, input and output tokens and cost for every LLM call, tagged by purpose and model. Watch the p95, not just the average: one slow call in a five-call turn makes the whole turn slow.

Terms on this page

TTFT
Time to first token: how long before the reply starts appearing.
KV cache
Stored attention state that lets a model reuse work for earlier tokens.
Quantization
Storing model weights with fewer bits to save memory and speed up inference.
