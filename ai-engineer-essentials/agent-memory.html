Agent memory: short and long term

Designing memory for AI agents: working memory in the context window, conversation summaries, long-term memory stores, retrieval of memories, user control and privacy.

Shubham Mishra2 min read

Users expect assistants to remember: what they said five messages ago, their preferences, the project they mentioned last week. Models remember nothing between calls. Every form of memory is a design decision about what to store, when to retrieve it and how much to put back into the prompt.

Three layers of memory

LayerLives inLifetimeExample
Working memoryThe context windowOne callThe last few messages and this turn's tool results
Conversation memoryYour message store, plus a running summaryOne conversation"The user is booking leave for 6–7 November"
Long-term memoryA memory store with retrievalAcross conversations"Prefers answers in Arabic", "Manages the payroll team"

Working and conversation memory

Keep recent messages verbatim within a token budget, and replace older ones with a short summary that is updated after each turn (see token window management). Store structured state, such as the current form or chosen entity, in your own data model rather than hoping the model infers it from the transcript.

Long-term memory

Long-term memory turns conversations into facts worth keeping:

  1. Extract: after a conversation, a small model proposes candidate facts: preferences, roles, recurring goals.
  2. Filter: keep only facts that are stable, useful and appropriate to store. Discard one-off details and anything sensitive unless the user asked you to remember it.
  3. Store: save each fact with its source conversation, a timestamp and an embedding.
  4. Retrieve: at the start of a turn, fetch the few memories relevant to the current message and add them to the prompt.
  5. Update: when a new fact contradicts an old one, replace it rather than keeping both.

Memory should never be authority

A remembered "the user is a manager" must not grant manager permissions. Permissions always come from the domain system at request time. Memory personalises answers; it does not authorise actions.

Give users control

  • Let users see what the assistant remembers about them.
  • Let them delete individual memories or turn memory off.
  • Tell them when a memory influenced an answer, where it matters.
  • Apply retention limits and honour deletion requests across every store, including vectors and caches.

See privacy and responsible AI for the wider picture.

Common failure modes

  • Stale memories that override what the user just said. The current message always wins.
  • Memory bloat: injecting dozens of memories into every prompt. Retrieve a handful.
  • Cross-user leakage: a missing user filter on the memory store. Scope every query by user and tenant, and test it.

Terms on this page

Working memory
What the model sees in the current context window.
Long-term memory
Facts saved across conversations and retrieved when relevant.
