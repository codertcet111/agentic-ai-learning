Token window management

Manage the LLM context window in chat agents: token budgets per section, recent-turn windows, summaries of older turns, compact tool results and measuring the effect in traces.

Shubham Mishra2 min read

Every LLM call has a context budget, and every token in it costs money and attention. Long conversations, large tool results and many capability cards compete for the same space. Window management decides what gets in.

Budget by section

Split the input into sections and give each a budget:

SectionExample budgetNotes
System prompt and policy1,500Stable; ideal for prompt caching
Capability cards2,500Filtered per agent and user
Conversation summary300Older turns, compressed
Recent turns2,000Last few exchanges, verbatim
Observations this turn1,500Tool result summaries, not raw payloads
Retrieved passages2,000Only when retrieval ran

Count tokens with the tokenizer for your model family, or a close approximation, and trim each section to its budget independently. One overflowing section should not push out the others.

Recent turns, by token count

Take messages from newest to oldest until the recent-turns budget is used. Always keep complete exchanges: do not include an assistant reply without the user message it answered. Drop UI-only blocks and keep their fallback text.

Summaries for older turns

When a conversation is long, maintain a short running summary of what came before the window: what the user is trying to do, decisions made, ids that matter. Update it asynchronously after a turn completes, using a small model, and store it on the conversation. Do not regenerate it on every turn.

Tool results: summarize, reference

A raw list of 200 transactions does not belong in a planner prompt. Give the planner a compact summary (count, totals, first few rows) and the step_result_id. Compose or the presentation layer loads full data when it needs it. See keeping GraphState small.

Order for caching

If your provider supports prompt caching, order sections from most stable to least stable: system prompt, policy, capability cards, summary, recent turns, this turn's observations. Anything that changes every call, such as a timestamp, goes last. This keeps the cached prefix long.

Measure every change

After changing the window strategy, compare input tokens per generation in your tracing tool for the same golden cases, and rerun the multi-turn cases. Some cases depend on information from several turns back. Those are the ones a too-aggressive window breaks.
