LLM Engineering

Day-to-day model integration: LiteLLM, structured outputs, stubs, and routing—from an implementer's chair.

Day-to-day model integration: LiteLLM, structured outputs, stubs, and routing—from an implementer's chair.

  • 01LiteLLM as a single gateway
    Route every model call through one gateway such as LiteLLM: model aliases in config, central timeouts and retries, fallbacks, token accounting and provider portability.
  • 02Structured outputs in production
    Get reliable structured outputs from LLMs in production: Pydantic schemas, provider-native JSON schema modes, semantic validation, a single repair attempt and safe failure.
  • 03LLM_STUB and deterministic CI
    Use a stub LLM (LLM_STUB) to run agent graph tests and golden cases deterministically in CI without API keys, and keep stub fixtures in sync with schemas.
  • 04Token window management
    Manage the LLM context window in chat agents: token budgets per section, recent-turn windows, summaries of older turns, compact tool results and measuring the effect in traces.
  • 05When to use small vs large models
    Decide when to use small versus large language models in an agent: route by purpose, measure with traces, escalate on low confidence and evaluate each tier on its own tasks.
  • 06Streaming responses to the client
    Stream LLM responses to chat clients safely: admit the turn first, stream only the compose step, handle client aborts, and reconcile the turn ledger so retries stay correct.
