When to use small vs large models

Decide when to use small versus large language models in an agent: route by purpose, measure with traces, escalate on low confidence and evaluate each tier on its own tasks.

Shubham Mishra2 min read

Using the largest available model for every call is simple and expensive. Using the smallest for everything is cheap and fragile. Most agents do best with a mix, chosen by what each call is for.

Route by purpose

PurposeTypical tierWhy
Routing between agentsSmallShort input, a few labels, easy to evaluate
Recipe miss classificationSmallSimple decision
Argument filling from clear textSmall or mediumMostly extraction
Planning with many tools or ambiguityLargeAccuracy here drives everything downstream
Composing nuanced or bilingual answersMedium or largeQuality is visible to users
Conversation summariesSmallRuns in the background, low stakes

Map each purpose to a gateway alias (LiteLLM as a single gateway), so the tiering lives in configuration.

Escalation

A useful pattern is to let the small model try first and escalate when it is unsure. The router's schema includes a confidence field. Below a threshold, the same input goes to a larger model. Use this where most inputs are easy and a few are hard. Verify with evaluation that the confidence actually correlates with correctness for your model and task. Self-reported confidence is not always reliable.

Prove the split with traces

Tag every generation with its purpose and model. Then a grouped view shows how many calls and tokens each tier handles. If the large model still accounts for most of the cost, look at which purpose is driving it, which is usually planning, and work on shrinking that prompt before changing tiers.

Evaluate each tier on its own job

When you move a purpose to a smaller model, run the golden cases tagged for that purpose, not just the full suite. Routing accuracy, argument correctness and compose quality each have their own measures. A small model that is 99% accurate at routing may be fine. One that is 92% accurate at planning probably is not.

Revisit regularly

Model prices and capabilities change quickly. A task that needed a large model last year may run well on this year's small one. Re-evaluate your tiering every few months with the golden suite. That is the only way to know.
