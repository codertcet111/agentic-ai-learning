Local Langfuse setup checklist

A checklist for setting up Langfuse tracing locally for an agent backend: environment variables, region, capture mode, first trace, and common reasons traces do not appear.

2 min read

Getting the first trace to appear is usually five minutes of configuration and, occasionally, an hour of wondering why nothing shows up. This checklist covers both.

1. Choose where Langfuse runs

  • Langfuse Cloud: create a project and copy its public and secret keys. Note which region your project is in, because the base URL differs per region.
  • Self-hosted: Langfuse publishes a Docker Compose setup for local use. Point the base URL at your local instance.

2. Environment variables

# Example: prefix them per your settings class
AGENTIC_LANGFUSE_ENABLED=true
AGENTIC_LANGFUSE_PUBLIC_KEY=pk-lf-...
AGENTIC_LANGFUSE_SECRET_KEY=sk-lf-...
AGENTIC_LANGFUSE_BASE_URL=https://cloud.langfuse.com     # or your region / local URL
AGENTIC_LANGFUSE_ENVIRONMENT=development
AGENTIC_LANGFUSE_CAPTURE=structure
AGENTIC_LANGFUSE_PSEUDONYM_KEY=<random secret>

Use one base URL consistently. If other libraries in the same process (for example an LLM gateway with its own Langfuse integration) read unprefixed LANGFUSE_* variables, make sure both point at the same project and region, or disable one integration. Otherwise you will get duplicate or missing traces.

3. Send one message

  1. Start the API with tracing enabled.
  2. Send one chat message, for example with the local make chat CLI.
  3. Open Tracing in Langfuse. A new trace should appear within a few seconds.

4. If nothing appears

  • Check startup logs for a clear disabled reason (missing keys, tracing turned off, wrong environment). Your startup code should log one.
  • Check keys and base URL belong to the same project and region.
  • Short-lived scripts must flush before exiting. SDKs batch events in the background, and a CLI that exits immediately can lose them.
  • Check outbound network access from the container or VM to the Langfuse host.
  • Check the environment filter in the Langfuse UI matches the environment you set.

5. Then verify the shape

Open the trace and confirm: the root observation is named as you expect, generations show model and token counts, tool spans show capability ids, and no tokens, emails or other sensitive values appear anywhere. Turn that last check into a test with the in-memory exporter (see testing observability hooks).
