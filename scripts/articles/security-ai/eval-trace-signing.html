Evaluation runs send realistic traffic through your assistant. You want that traffic to be recognisable: routed to an experiment in your tracing tool, excluded from usage dashboards and product metrics, and allowed to use test fixtures. But "recognisable" must not mean "anyone can claim to be a test", because test mode can unlock behaviour you never want real users to reach.

Sign the eval request

The eval runner signs each request with a key only CI has:

timestamp = str(int(time.time()))
body_hash = sha256(body).hexdigest()
message = f"{timestamp}.{run_id}.{case_id}.{body_hash}"
signature = hmac.new(EVAL_SIGNING_KEY, message.encode(), "sha256").hexdigest()

headers = {
  "X-Eval-Run": run_id,
  "X-Eval-Case": case_id,
  "X-Eval-Timestamp": timestamp,
  "X-Eval-Signature": signature,
}

The server recomputes the HMAC with its copy of the key, compares it in constant time, and rejects timestamps older than a few minutes to prevent replay.

What a valid signature unlocks

  • Traces are tagged with the run and case ids and grouped as an experiment.
  • Usage counters and product analytics skip the turn.
  • The stub LLM or recorded upstream fixtures may be selected, but only in non-production environments.

An invalid or missing signature means the request is treated as normal traffic. Unsigned requests claiming to be evals are logged as a security event.

Keep keys out of production

The signing key exists in CI secrets and in non-production environments. Production either has no eval key at all, so eval headers are ignored, or a separate key that only enables tagging, never fixtures or stubs. Rotate keys on a schedule and whenever someone with access leaves.

Why not just an API key header?

A fixed "test mode" header is a shared secret that leaks easily: into logs, into browser developer tools, into screenshots. A signature over the timestamp and body is useless once it expires and cannot be reused for a different request. The extra code is small.
