Streaming makes an assistant feel fast: the first words appear in under a second instead of after the whole answer is ready. In an agent, though, most of the turn is planning and tool calls, which have nothing to stream. Streaming needs to fit around the graph, not replace it.

What to stream

  • Progress events during planning and tool calls: "Checking your leave balance…". These are short status messages tied to graph nodes, not model tokens.
  • Compose tokens: the final answer, streamed as it is generated.
  • Structured blocks (tables, cards, forms): sent as complete events when ready, never token by token.

Transport

Server-sent events (SSE) are the usual choice: plain HTTP, easy through proxies and load balancers, and natively supported by browsers. Use typed events:

event: turn.accepted     data: {"turn_id": "trn_88", "revision": 15}
event: progress          data: {"node": "invoke", "label_key": "checking_balance"}
event: text.delta        data: {"text": "You have "}
event: text.delta        data: {"text": "12 days left."}
event: block             data: {"type": "table", ...}
event: turn.completed    data: {"message_id": "msg_…", "sequence": 42}

Order of operations

  1. Admit the turn first (fence, ledger entry). Only then open the stream with turn.accepted. A rejected turn gets a normal HTTP error, not a stream.
  2. Run the graph, emitting progress events.
  3. Stream compose tokens as they arrive.
  4. Persist the final message and complete the ledger entry, then send turn.completed with the stored message id.

The persisted message is the source of truth. Clients that lose the connection fetch it by sequence rather than trying to reassemble partial deltas.

Aborts

When the user presses Stop or closes the tab:

  • If the turn is still planning or invoking reads, cancel the graph run and mark the ledger cancelled.
  • If a write is in flight, let it finish. Cancelling mid-write leaves the user unsure whether it happened. Persist the result, and show it when they return.
  • If compose is streaming, stop generation and persist what was produced with a "stopped" marker, or discard it. Choose one behaviour and keep it consistent.

Retries

A client that reconnects with the same client_request_id must not start a second run. Admission returns the existing turn's state: still running (reattach or poll) or completed (here is the message). See idempotency patterns.
