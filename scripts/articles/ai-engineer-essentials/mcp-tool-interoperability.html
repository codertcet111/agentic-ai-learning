Every agent needs tools, and for a long time every framework described tools its own way. The Model Context Protocol (MCP) is an open standard, introduced by Anthropic in late 2024 and since adopted widely, for connecting AI applications to tools and data through one common interface. Write a tool integration once as an MCP server, and any MCP-capable application can use it.

The moving parts

  • Host: the AI application the user interacts with, such as a desktop assistant, an IDE or your own agent backend.
  • Client: the connector inside the host that talks to one server.
  • Server: a program that exposes capabilities, for example "search tickets" or "read this database".

What a server can offer

PrimitiveWhat it isExample
ToolsFunctions the model can call, with a JSON Schema for inputscreate_ticket(title, priority)
ResourcesData the application can read and put in contextA file, a database row, a document
PromptsReusable prompt templates the user can pick"Summarise this incident"

Messages use JSON-RPC. Servers run either locally, talking to the host over standard input and output, or remotely over HTTP, usually with OAuth for authorisation.

How it relates to your agent backend

MCP describes the same idea as the capability catalog in the 20-step path: named tools, typed parameters and a clear owner. You can use it on either side:

  • As a client: your orchestrator connects to existing MCP servers instead of writing a custom provider for each service.
  • As a server: you wrap your domain APIs as an MCP server, so assistants and IDEs across your company can use them with the same permissions as your own agent.

Security still lives with you

A standard interface does not make a tool safe. Treat MCP servers like any other integration:

  • Least privilege: expose only the tools a use case needs, scoped to the signed-in user.
  • Confirm writes: tools that change data should require explicit confirmation (see write confirmation).
  • Trust carefully: a third-party server's tool descriptions and outputs reach your model's context. Malicious descriptions or results are a prompt-injection channel. Install servers only from sources you trust and review what they expose.
  • Audit: log every tool call with user, arguments (redacted) and result status.

Agent-to-agent protocols

MCP connects an agent to tools. A separate group of protocols, such as the Agent Communication Protocol and Agent2Agent, focus on agents talking to other agents: discovering each other, delegating tasks and exchanging results. They are younger and still settling, so design your own agents with clean, typed boundaries that can be exposed through whichever protocol your ecosystem standardises on.

Getting started

  1. Pick one read-only internal API that several teams would like assistants to use.
  2. Wrap it as an MCP server using an official SDK, with clear tool descriptions and input schemas.
  3. Forward the user's identity so the API enforces its normal permissions.
  4. Test it from an MCP-capable desktop app, then from your own orchestrator.
