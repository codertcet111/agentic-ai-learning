Langfuse lets you attach scores to traces and observations: numeric, boolean or categorical values with a name and an optional comment. Scores turn a pile of traces into something you can chart, filter and compare across releases.

Where scores come from

  • Eval runs in CI: the golden runner scores each case's trace (routing correct, tools correct, within budget).
  • Automatic turn checks in production: budgets checked when each turn finishes (see turn checks).
  • LLM judges: groundedness or helpfulness on a sample of traces.
  • User feedback: thumbs up or down from the UI, attached to the trace.

Attaching a score

With the Langfuse Python SDK, scores are created against a trace id, and optionally an observation id. The exact method name has changed between SDK versions, so check the documentation for the version you install. The shape is:

langfuse.create_score(
    trace_id=trace_id,
    name="routing_correct",
    value=1,                       # numeric or boolean
    data_type="BOOLEAN",
    comment="expected hr_assistant, got hr_assistant",
)

Keep score names stable and few. Renaming tool_correct to tools_ok halfway through a quarter breaks every chart.

Tag releases and environments

Set the release (your version or commit) and environment on every trace. Then the Langfuse UI and API can group scores by release: "tools_correct was 0.97 on 2026.10.20 and 0.91 on 2026.10.28" is a regression you can act on. Without release tags, you can only see that something changed at some point.

Separate eval traffic

Keep CI eval traces distinguishable from user traffic, either in a separate Langfuse project or with a clear tag. Langfuse datasets and experiment runs are designed for this: each golden case becomes a dataset item, and each CI run becomes an experiment you can compare with earlier ones. See also signed eval traces.

Act on trends

Review score dashboards weekly, not only when something breaks. A slow decline in within_llm_call_budget often means the catalog is growing and tool descriptions are starting to overlap, and it is much easier to fix early.
