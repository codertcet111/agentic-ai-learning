The golden runner is the command you will use more than any other while working on prompts and graph changes. It needs to be fast in the common case, honest in the nightly case, and produce output you can read in a terminal.

Two modes

Stub modeLive mode
LLMScripted fixturesReal models via gateway
UpstreamFake responsesFake responses or sandbox
SpeedSeconds for hundreds of casesMinutes
CostFreeReal tokens
ProvesPlumbing, persistence, flowsModel decisions
WhenEvery pull request, locally all the timeNightly, and on prompt or model changes

Commands

evals run                              # stub mode, all cases
evals run --tags leave,write           # subset while working on a feature
evals run --case leave.request.ambiguous-approver.en -v   # one case, verbose
evals run --live --tags routing --repeat 3                 # real model, 3 runs each
evals diff --baseline baselines/2026-10-20                 # compare with approved run

Repeats for live runs

Real models vary between runs. Run each live case several times and report pass rates, for example "routing correct 5/5, tools correct 4/5". A case that drops from 5/5 to 3/5 after a change is a real regression even though it "passed" once.

Reports

The runner writes JSON results and a Markdown summary. CI attaches the summary to the pull request: totals by tag, newly failing cases, and the trace-diff highlights (node sequences, LLM calls, tokens). Reviewers then see behaviour changes next to code changes.

Tagging strategy

Tag by domain (leave, orders), by risk (write, safety), by shape (multi-turn, ambiguity) and by language. Release gates use the risk tags. Day-to-day work uses the domain tags.
