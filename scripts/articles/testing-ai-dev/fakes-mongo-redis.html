Graph and service tests should run in seconds, without Docker. The way to get there is to put persistence behind small repository interfaces and give each interface an in-memory fake. The real MongoDB and Redis are tested separately, in a smaller set of integration tests.

Repository interfaces

class MessageRepo(Protocol):
    async def append(self, msg: NewMessage) -> StoredMessage: ...
    async def list_after(self, conversation_id: str, seq: int, limit: int) -> list[StoredMessage]: ...

class TurnLedgerRepo(Protocol):
    async def begin(self, conversation_id: str, client_request_id: str) -> TurnEntry: ...
    async def complete(self, turn_id: str, message_id: str) -> bool: ...

Services and graph nodes depend on these protocols, never on the database driver directly.

Fakes that behave like the real thing

A fake is only useful if it enforces the same rules as the real store. The important ones:

  • Unique constraints: appending a duplicate idempotency key raises the same DuplicateKey error your Mongo repository raises.
  • Conditional updates: complete() returns False if the turn is not in the expected state, just like a zero-match update.
  • Ordering: list_after sorts by sequence.
  • Copies: return copies of stored objects, so tests cannot accidentally mutate "database" state through a reference.

One contract suite for both

Write the repository tests once and run them against both implementations:

@pytest.fixture(params=["fake", pytest.param("mongo", marks=pytest.mark.integration)])
def message_repo(request, mongo_db):
    return FakeMessageRepo() if request.param == "fake" else MongoMessageRepo(mongo_db)

async def test_duplicate_idempotency_key_raises(message_repo): ...

If the fake and the real repository ever disagree, this suite finds it.

Redis fakes

For Redis, a library such as fakeredis covers most commands in memory. For the graceful-degradation tests, also use a fake that raises connection errors on every call. That is the simplest way to prove the system works with Redis down.

Markers

# pyproject.toml
[tool.pytest.ini_options]
markers = ["integration: needs real MongoDB/Redis (docker compose up)"]
addopts = "-m 'not integration'"

Developers run the fast suite constantly. CI runs both, with integration tests against service containers.
