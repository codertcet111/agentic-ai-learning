Local dev topology

A local development setup for agentic backends: MongoDB and Redis in Docker Compose, sandbox upstream APIs, a stub LLM, environment files and a fast feedback loop.

2 min read

A good local setup lets you run a full chat turn on your laptop in seconds, without production credentials and, for most work, without paying for model calls. Here is a topology that works.

Services

# docker-compose.yml
services:
  mongo:
    image: mongo:7
    ports: ["27017:27017"]
    command: ["--replSet", "rs0"]   # replica set enables transactions and change streams
  redis:
    image: redis:7
    ports: ["6379:6379"]
  fake-upstream:
    build: ./dev/fake_upstream      # small FastAPI app serving fixture responses
    ports: ["8081:8081"]

A single-node replica set takes one extra init command (rs.initiate()) and gives you transactions and change streams, matching most production clusters.

Upstream: fake, sandbox or both

  • Fake upstream: a tiny local server returning fixture JSON for each capability, including error cases on special inputs (an employee named "Error503" returns 503). Fast, deterministic, works offline.
  • Sandbox APIs: the real services' non-production environments with test data. Use them to check contracts before merging provider changes.

Switch between them with configuration, never with code changes.

The LLM

  • LLM_STUB=true: canned structured outputs keyed by golden case, so there are no keys and no cost (see LLM_STUB).
  • Real models through your gateway with a development key and a low spending limit, for prompt work.

Environment file

# .env.local  (never committed; .env.example is)
APP_ENV=development
MONGO_URI=mongodb://localhost:27017/?replicaSet=rs0
REDIS_URL=redis://localhost:6379/0
UPSTREAM_HR_BASE_URL=http://localhost:8081
LLM_STUB=true
LLM_DEFAULT_MODEL=dev-small
LANGFUSE_ENABLED=false
DEV_FAKE_AUTH_TOKEN=Bearer dev-token-employee-basic

Mirror production header names exactly (Authorization, Accept-Language, X-Request-Id), so that code paths behave the same locally.

Fast loop

make up          # compose services
make dev         # run the API with reload
make chat        # small CLI: sends a message, prints reply and node sequence
make test        # unit + graph tests with fakes and stub LLM (seconds)
make evals       # golden suite with stub LLM

The make chat CLI is worth the hour it takes to write. Printing the node sequence and LLM call count for each message gives you most of what a trace UI shows, right in your terminal.

Turn on tracing when needed

Run Langfuse locally with its Docker Compose setup, or point at a development project in Langfuse Cloud, when you are working on prompts or performance. Keep it off by default, so the inner loop stays fast. See the local setup checklist.
