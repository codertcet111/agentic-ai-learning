Cost and rate limits

Control LLM costs in production agents: per-turn token and call caps, model routing, prompt caching, catalog trimming, rate limits per tenant and budget alerts.

2 min read

LLM costs scale with usage and with carelessness. A prompt that grew by 2,000 tokens, a planner that loops once more than needed, or one tenant's automated script can each double a monthly bill. Cost controls are guardrails you put in place before you need them.

Know where tokens go

Tag every LLM call with a purpose (route, plan, resolve, compose, judge) and record input and output tokens. A weekly breakdown by purpose usually shows that planning dominates, and within planning, the capability cards and transcript window are the bulk of input tokens. Optimize what the numbers point at.

Per-turn caps

  • Max LLM calls per turn (for example 8): when reached, stop planning and compose with what you have.
  • Max input tokens per call: the window builder trims the transcript to fit.
  • Max output tokens per purpose: planners need few, compose needs more.
  • Graph recursion limit: a hard backstop for loops.

Shrink the prompt

  • Filter the catalog per agent and per user. Twelve relevant tools beat sixty, for both cost and accuracy.
  • Summarize tool results in state instead of passing raw payloads to the planner.
  • Trim the transcript window by token budget, and summarize older turns.
  • Use prompt caching where your provider supports it. Put stable content (system prompt, policy, capability cards) first and variable content last, so the stable prefix is cached and billed at a lower rate.

Route by difficulty

Use a smaller, cheaper model for routing, classification and simple argument filling, and a larger model for planning ambiguous requests and composing nuanced answers. Recipes (step 15) skip the model entirely for known commands. See model routing.

Protect against noisy neighbours

  • Rate limits per principal per minute, in Redis.
  • Daily token quotas per tenant, checked during turn admission.
  • Circuit breakers on tools that fail repeatedly, so retries do not trigger extra planning.

Cache what is safe to cache

Cache merged catalogs, capability snapshots and short-lived lookup results. Do not cache LLM responses to user messages across users. The privacy risk and stale-answer risk outweigh the savings for most assistants.

Alerts

  • Daily spend estimate above a threshold per environment.
  • Tokens per turn p95 rising week over week.
  • Any single tenant above a set share of total usage.

Review the cost dashboard after every release that touches prompts or the catalog. Cost regressions are much easier to fix the day they ship.
