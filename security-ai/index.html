Threat models and patterns for auth-forwarding orchestrators.

Threat models and patterns for auth-forwarding orchestrators.

  • 01Token forwarding, never token storage
    Secure an AI orchestrator with token forwarding instead of token storage: per-request context, no shared cookie jars, scoped outbound calls and redaction at every exit.
  • 02Three-layer authorization
    Apply three layers of authorization in AI agents: what the planner is shown, what the orchestrator allows at invoke time and what the upstream API finally enforces.
  • 03Writes and explicit confirmation
    Protect data-changing actions in AI assistants with explicit confirmation: graph-enforced confirmation steps, fingerprints, explicit action flags and operation ids against duplicates.
  • 04Signed eval traces
    Sign automated evaluation traffic so CI runs can be identified, routed to experiment traces and given test-only behaviour, without exposing signing keys to production.
