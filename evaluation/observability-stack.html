Observability stack choices

Choose an observability stack for AI applications: structured logs, distributed tracing and APM, LLM-specific observability like Langfuse, and error tracking, tied together by ids.

2 min read

An agentic backend is a web service, a workflow engine and an LLM client at the same time. Each of those has mature observability tools, and no single tool covers all three well. A practical stack combines four pieces and links them with shared identifiers.

The four pieces

PieceAnswersExamples
Structured logsWhat happened, in order, for this request?JSON logs to Loki, Elasticsearch, CloudWatch, Datadog Logs
Distributed tracing / APMWhere did the time go across services?OpenTelemetry with Jaeger, Tempo, Datadog APM, Honeycomb
LLM observabilityWhat did the model see and say, and what did it cost?Langfuse, Arize Phoenix, LangSmith and similar
Error trackingWhich exceptions are new and how often do they occur?Sentry, Rollbar

Tie them together with ids

Every log line, span and error event carries request_id. LLM traces also carry conversation_id and turn_id. With that, an engineer can start anywhere, whether an alert, a user report or an error, and reach the others in one search. Without it, you have four tools and no story.

Structured logs

Log JSON with consistent keys: ts, level, event, request_id, tenant (pseudonymized), turn_id, node, duration_ms. Use event names, not sentences: event="capability_invoked" with fields is searchable, while "Invoked capability leave.balance.read in 230ms" is not.

Tracing and APM

OpenTelemetry instrumentation for your web framework, HTTP client and database driver gives request-level spans almost for free. Add the agent spans described in step 18. APM answers questions like "is the HR API slow for everyone, or only for this endpoint?"

LLM observability

LLM-focused tools understand prompts, completions, token usage, cost and evaluation scores, and present them in a way general APM does not. Many now accept OpenTelemetry data, so you can send the same spans to both. See the Langfuse Lab section for a walkthrough of one such tool.

Error tracking

Uncaught exceptions go to an error tracker with release tags, so you can see which deploy introduced a new error. Configure scrubbing before anything else: request headers, cookies and local variables can contain tokens and personal data.

Privacy across all four

Each tool is another copy of your data. Decide once what may be sent (identifiers pseudonymized, no tokens, prompt text only in approved environments or masked modes) and enforce it in shared logging and exporter code, not by convention.

Start small

If you are building the first version, start with structured logs plus one LLM observability tool, linked by request id. Add APM when you have several services, and error tracking once you have real users. The ids matter more than the tools.
