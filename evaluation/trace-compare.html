Trace compare across releases

Compare agent traces across releases: run golden cases, export node sequences, LLM call counts, tokens and latency, and diff them against an approved baseline.

Shubham Mishra2 min read

Pass/fail tells you whether a golden case still meets its expectations. It does not tell you that the case now takes five LLM calls instead of three, or that a refactor reordered two nodes. Trace comparison catches those quieter changes.

What to extract from each trace

{
  "case_id": "leave.balance.basic.en",
  "release": "2026.10.28",
  "nodes": ["load_session", "route", "plan", "resolve", "invoke", "plan", "compose"],
  "llm_calls": [{"purpose": "plan", "model": "large", "in": 2810, "out": 64},
                {"purpose": "plan", "model": "large", "in": 3020, "out": 41},
                {"purpose": "compose", "model": "large", "in": 1210, "out": 88}],
  "capabilities": ["leave.balance.read"],
  "total_tokens": 7233,
  "latency_ms": 2840
}

This summary is small, stable and can be diffed. Produce it by walking the spans (from your tracing backend's API, or an in-memory exporter during the eval run) and keeping only names, counts and numbers, never text.

Baselines

After a release is approved, store its summaries as the baseline. Each new run is compared against the most recent baseline, not against the previous unapproved run, so regressions do not quietly become the new normal.

What the diff shows

leave.balance.basic.en
  nodes:        + evaluate_condition  (after invoke)
  llm_calls:    3 → 4   (+1 plan)
  total_tokens: 7233 → 9871  (+36%)
  latency_ms:   2840 → 3610  (+27%)

A report like this, generated in CI and attached to the pull request, turns "the assistant feels slower" into a specific change with a specific cause.

Thresholds

  • Node sequence changed: always flag it for review. It may be intended, but someone should confirm.
  • LLM calls increased: flag any increase on cases tagged as simple.
  • Tokens: flag increases above 15–20%. Small noise is normal with real models.
  • Latency: compare medians over several runs. A single run is too noisy.

Real models are not deterministic

With live models, the same case can take slightly different paths on different runs. Run each case several times (three to five) and compare distributions: "planned twice in 4 of 5 runs, previously 1 of 5" is a real signal, while one run differing is not. With the stub LLM, runs are deterministic and any diff is a code change.

Tooling

Langfuse supports grouping evaluation traces into datasets and experiment runs and comparing them side by side, which covers much of this. A small script that produces the JSON summaries and a Markdown diff is still worth having. It works in CI, needs no UI, and its output can be committed next to the baseline.

Terms on this page

Span diff
Comparison of node order between two runs.
Baseline
Approved trace from a known-good release.
